## 2. 利用環境

マルチデバイス対応を基本とし、最初はWebブラウザベースで提供。

- **ハードウェア**: スマートフォン（iOS/Android）、PC（Windows/Mac）、タブレット
- **ソフトウェア**:
    - モバイル：Safari, Google Chrome 最新版
    - PC：Google Chrome, Microsoft Edge, Safari 最新版
- **OS制限**: 特になし（最新のWebブラウザが動作すること）
- **専用ハードウェア**: 不要

## 4. 機能要件

正常系における主要機能は以下の通りである。

| **機能名** | **内容詳細** | **取り扱うデータ** |
| --- | --- | --- |
| **認証機能** | 全学計算機システム(MS365)等のアカウントを用いたログイン | 氏名、メールアドレス、学籍番号 |
| **ガイド・案内（サジェスト）機能** | ユーザー属性に合わせ、「今知るべき情報」を表示 | 学年、所属、興味関心タグ、閲覧履歴 |
| **検索・フィルタ機能** | 全情報（授業、過去問、店等）を横断的に検索 | 検索キーワード、カテゴリ、タグ |
| **授業・過去問共有機能** | 授業の口コミ投稿および試験資料の共有 | 授業名、担当教員、評価、コメント、PDF/画像ファイル |
| **サークル・団体管理** | 各団体が自身の活動情報を登録・編集する機能 | 団体名、活動場所、時間、新歓情報、SNSリンク |
| **就活・インターン管理** | インターン締切等をカレンダー形式で表示 | 企業名、締切日、イベント内容、URL |
| **情報集約（クローリング）** | 大学公式サイトや既存サービスの情報を自動取得 | サイトURL、お知らせタイトル、本文、日付 |
| **ブックマーク機能** | 気になる記事や授業情報を保存する | ユーザーID、対象コンテンツID |
| **カレンダー機能** | 学年歴、ほかの機能との連携(e.g. サークルの新歓、課題締め切り、インターンetc.) | 日付情報、興味関心タグ、新歓情報、締切日 |
| **学食情報** | 筑波大学の学食の詳細・口コミを掲載 | 食堂の名前、メニュー、評価、コメント |
| **マップ機能** | えりたんに飛ばした方が楽。 |  |
| **通知機能** | 必要な情報が上がったときに通知 | ユーザー属性、興味関心タグ |

## 5. 非機能要件

### 5-1. 性能

- **同時接続数**: 履修登録期間等のピーク時に数千名が同時アクセスしても停止しないスケーラビリティ

### 5-2. 可用性

- **メンテナンス**: 大学の履修登録期間等の重要時期を避け、深夜帯に実施する
- **オフライン時の扱い**: オフライン時はキャッシュされた情報のみ表示し、新規投稿や検索は不可とする

## 6. データ要件

データベースの主要なテーブル構成案

| **テーブル名** | **役割** | **主要カラム（型）** |
| --- | --- | --- |
| **Users** | ユーザー情報 | user_id(INT), email(VARCHAR), grade(INT), college(VARCHAR) |
| **Courses** | 授業情報 | course_id(INT), title(VARCHAR), instructor(VARCHAR), term(VARCHAR) |
| **Reviews** | 評価・口コミ | review_id(INT), user_id(INT), target_id(INT), rating(INT), comment(TEXT) |
| **Files** | 過去問等のファイル | file_id(INT), review_id(INT), s3_url(VARCHAR), file_type(VARCHAR) |
| **Organizations** | 団体情報 | org_id(INT), name(VARCHAR), category(VARCHAR), description(TEXT) |
| **Events** | インターン・行事 | event_id(INT), title(VARCHAR), date(DATETIME), link_url(VARCHAR) |

## 7. 外部連携要件

- **Twin:te (既存サービス)**: 連携ボタンの設置、またはAPIを通じた時間割データの参照（検討中）
- **大学公式サイト**: RSSフィードやクローリングによる最新ニュースの自動取り込み
- **マップ**: 飲食店や大学施設の位置情報表示におけるAPI連携
- **SNS (Twitter / LINE)**: 情報のシェア機能
    - 過去問情報など共有できる

## 8. セキュリティ要件

- **学内限定アクセス**: 基本的に筑波大生（@s.tsukuba.ac.jp等のドメイン）のみが投稿・詳細閲覧できるよう制限する
- **データ保護**: 通信はすべてHTTPS化する。個人を特定しすぎる情報の投稿に対するガイドラインの設置。
- **不適切コンテンツ対応**: 通報ボタンを設置し、管理者による削除フローを設ける。
