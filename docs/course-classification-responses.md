# 未分類科目の分類回答と候補提示

> 現在、このDB機能はUIへ接続していない。未分類科目の「分類」はページ内の判定結果だけを
> 再計算し、DB保存や候補取得を行わない。この文書は将来接続する場合の設計を記録する。

卒業要件チェックで `uncountedCourses` になった科目について、利用者が選択した区分を
`course_classification_responses` に匿名の回答として蓄積する。別の利用者が同じ科目を
未分類として検出したとき、回答の集計結果を分類候補として提示する。

将来接続する場合も、候補は参考情報とし、利用者が確認して採用した場合だけ判定結果へ反映する。

## 保存形式

| 列 | 用途 |
| --- | --- |
| `university_id` | 大学ごとの集計境界 |
| `course_code` | 科目番号。空の場合も許容 |
| `course_name` | 科目番号が変わった場合にも照合できる科目名 |
| `respondent_department` | 卒業要件確認時に選択した回答者学類 |
| `respondent_major` | 回答者の主専攻。存在しない場合はNULL |
| `classification` | 利用者が選択した区分 |
| `created_at` | 回答日時。運用・監査用 |

開講年度、回答者の入学年度、使用した卒業要件ID、回答者ユーザーIDは保存しない。
生の成績、評価、単位数、CSVファイルも保存しない。

`classification` は次の6値に限定する。

- `compulsory`: 必修科目
- `specialized`: 選択科目（専門）
- `specialized_foundation`: 選択科目（専門基礎）
- `common`: 選択科目（共通）
- `related`: 選択科目（関連）
- `not_counted`: 卒業要件の対象外

## 候補の集計

候補取得は、画面内の未分類科目をまとめて `get_course_classification_suggestions` RPCへ渡す。
科目数にかかわらず1回の通信で取得するため、科目ごとの問い合わせは発生しない。

同じ大学の回答から、次のいずれかに一致する回答を年度横断で集計する。

- 正規化した科目番号の完全一致
- 前後空白と大文字・小文字を正規化した科目名の完全一致

回答者の背景が近い候補を優先するため、回答ごとの重みを次のようにする。

- 同じ学類かつ同じ主専攻: 3
- 同じ学類: 2
- その他: 1

重み付き得点が最大の区分を提案し、同点の場合は回答数を優先する。年度や卒業要件IDでは
絞らないため、年度変更後も過去の回答を候補提示に利用できる。

## アクセス制御と重複回答

回答の追加はログイン済み利用者に限り、所属大学と同じ `university_id` だけをRLSで許可する。
生の回答一覧は通常利用者へ公開せず、候補提示用RPCは集計結果だけを返す。候補の参照は
ログイン前でも可能である。

ユーザーIDを保存しないため、DB上で「同じ利用者の回答は1件だけ」という制約は設けられない。
現在の画面では保存成功後の再送信を無効化する。意図的な連続投稿への対策が必要になった場合は、
ユーザーIDを回答行へ残さず、RPCやEdge Function側の短時間レート制限として追加する。
