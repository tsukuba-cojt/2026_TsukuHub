# 卒業要件チェッカー テスト仕様書

作成日：2026年11月6日

## 1. 目的と対象

`src/features/graduationCheck/tests/` にある既存の自動テストが保証する動作、入力条件、期待結果、実行方法を定義する。新規テストの計画ではなく、現在のテストコードと固定期待値に基づく仕様書である。大学の卒業認定そのものの正当性を保証するものではない。

対象はCSV解析、適用要件の選択、必修・選択科目判定、単位集計、GPA・A率、科目分類、年度別カタログ、要件データの検証である。画面操作、同意、認証、DB保存、画面遷移は対象外。テスト名に「E2E」がある場合も、本ディレクトリでは判定ロジックの結合テストを指す。

以下のファイル名は、特記しない限り `src/features/graduationCheck/tests/` からの相対パスである。

## 2. テスト構成と前提

| 層 | 入力と実行方法 | 判定方法 |
| --- | --- | --- |
| 単体・ロジック結合 | Vitestで科目オブジェクトやCSV文字列を入力 | 各テストの固定値・配列・オブジェクトと比較 |
| データ検証 | 固定カタログ、正規化要件、要件定義を読み込む | 出典・構造・年度差・分類規則を検証 |
| CSV統合 | PythonからTypeScriptランナーを呼び出す | CSVごとの `.expected.json` と比較 |

プロジェクトに対応するNode.js、npm依存パッケージ、Python 3.10以上を使用する。Pythonの追加パッケージは不要。CSV統合ではTypeScriptを一時ディレクトリにコンパイルし、終了時に削除する。

## 4. CSV統合テスト仕様

対象は `script/test_graduation_check.py` と `script/run_graduation_check.ts`。本番の `resolveRequirementId`、`parseGradesCsv`、`checkGraduationWithCatalog` を使用する。fetchのみを `public/data/graduation/` のファイル読み込みへ置換し、CSV解析・分類・集計はモック化しない。

### 4.1 入力データ

`data/*.csv` と同名の `*.expected.json` を1対1で配置する。既存データは70組で、25学類・専門学群、49専攻・課程、70種類の要件IDを扱う。選択条件はJSONの `selection.departmentKey`、`majorKey`、`admissionYear` に指定する。

全ケースの選択条件・必要単位・確定／見込み単位は [COVERAGE.md](../src/features/graduationCheck/tests/data/COVERAGE.md)、科目出典は [COURSE_SOURCES.md](../src/features/graduationCheck/tests/data/COURSE_SOURCES.md) を参照する。架空の成績であり、既存科目の一部は分類検証用の番号・単位を維持しているため、実在科目との完全一致を前提としない。

入学年度と開講年度は別の入力である。2023〜2026開講は静的カタログで照合し、2021・2022開講は未対応年度としてCSV情報で判定する。

### 4.2 検証項目と合格条件

| ID | 条件・入力 | 期待結果 |
| --- | --- | --- |
| CSV-01 | データ探索 | CSVが1件以上あり、CSVとJSONの名前集合が一致する |
| CSV-02 | 期待値の構成 | courseCountが正。csvErrors・summary・categories・gpa・assignmentsキーが存在する |
| CSV-03 | 各CSVを解析・判定 | ランナー正常終了。科目数・エラー・要件ID・カタログ年度・集計等、JSONに指定した値が一致する |
| CSV-04 | 全科目の割当 | assignmentsが完全一致し、その件数が解析科目数に一致する |
| CSV-05 | 評価混在 | A+/A/B/Cは合格単位。Dは分類を保持するが取得単位へ含めずGPAへ含める。履修中は上限内の見込みのみ。認/Pは合格単位のみ、Fは取得単位・GPA・A率から除外 |
| CSV-06 | 科目番号なし認定 | 未分類として保持し、関連科目へ推測配分しない |

assignments以外のオブジェクトは指定キーの部分一致、配列は長さ・順序・各要素を比較する。期待値が浮動小数点なら `assertAlmostEqual(..., places=9)`、その他の値は等値比較する。未指定のレポート項目まで検証するものではない。

割当値は `compulsory`、`specialized`、`specializedFoundation`、`common`、`related`、`uncounted`。科目番号をキーとするためケース内で番号を重複させず、番号なしは1件までとする。

## 5. 実行・結果の確認

プロジェクトルートで実行する。

```bash
npm ci
npm test -- src/features/graduationCheck/tests
python3 src/features/graduationCheck/tests/script/test_graduation_check.py
```

`npm ci` は依存導入時に行う。VitestとPythonは別の入口であり、`npm test` のみではPython統合テストは実行されない。Pythonは1テスト内のサブテストとして各CSVを実行し、失敗時にCSV名・比較項目を表示する。コンパイルのタイムアウトは120秒、CSVごとのNode実行は30秒。

合格条件は両コマンドが終了コード0で完了し、全アサーションが成功すること。実行記録にはコミット、実行日、環境、件数、失敗箇所を残す。本書の作成はテスト実行結果の証明を兼ねない。

## 6. 保守と網羅範囲

要件や年度を追加する際は選択肢・単位内訳・代表科目・年度境界を対応するVitestに追加し、必要なCSVと期待JSONを追加する。期待値は履修要覧や独立計算で確認し、テスト実行時に本体の出力から生成しない。CSV追加時はケース一覧と出典一覧も更新する。

現状の要件ID網羅は、全入学年度・全科目・全判定分岐の網羅を意味しない。正常な卒業充足、通信失敗、画面操作等についても本書に記載のないケースまで検証済みとは扱わない。コードカバレッジの合格閾値や大学側の受入基準は本書では新たに定めない。
