# 卒業要件チェックの現状の判定方法

このドキュメントは、現在の実装に基づいて、卒業要件チェックがどのように動いているかを整理したものです。

## 1. 概要

現在の卒業要件チェックは、TWINS の成績 CSV をアップロードすると、ブラウザ上で卒業要件の充足状況を判定し、結果画面に表示する流れで実装されています。

- 判定はすべてクライアント側で完結します。
- サーバー送信は行っていません。
- 判定ロジックは、必修科目・選択科目・単位集計・GPA・A率を順に処理する構成です。
- 要件データは「学類 × 専攻 × 入学年度」によって切り替えられます。

## 2. 実行フロー

1. ユーザーが学類・専攻・入学年度を選択する
2. TWINS の成績 CSV をアップロードする
3. CSV をパースして科目の一覧を作る
4. 選択された卒業要件データを読み込む
5. 必修判定を実行する
6. 残った科目で選択判定を実行する
7. グループ単位・5区分・全体サマリーを集計する
8. GPA と A 率を算出して結果ページに渡す

## 3. 主要な実装箇所

- アップロード画面: src/pages/GraduationCheck.tsx
- 判定エンジン本体: src/features/graduationCheck/checkGraduation.ts
- CSV パース: src/features/graduationCheck/parseCsv.ts
- 必修判定: src/features/graduationCheck/checkCompulsory.ts
- 選択判定: src/features/graduationCheck/checkSelect.ts
- GPA / A 率計算: src/features/graduationCheck/gpa.ts
- 5区分マッピング: src/features/graduationCheck/categoryMapping.ts
- 結果表示: src/pages/GraduationCheckResult.tsx

## 4. CSV 解析の処理

CSV は、TWINS の成績データをそのまま読み込み、各科目を以下の情報を持つオブジェクトに変換します。

- 科目番号
- 科目名
- 単位数
- 総合評価
- 開講年度

### パース時のルール

- 1 行目はヘッダーとしてスキップします。
- 列位置を固定で読み取ります。
- 科目名が空、単位数が数値でない、評価が不明、年度が数値でないものはエラーとして記録します。
- 読み取れた科目がある場合は、エラーがあっても判定を継続します。

### 対応する評価

次の評価を受け付けます。

- A+
- A
- B
- C
- D
- P
- F
- 認
- 履修中

## 5. 必修判定のルール

必修要件は、各要件文字列を順に読み、対応する科目を探します。判定の際には、マッチした科目を「消し込み」によって候補から外します。これにより、後続の選択判定で同じ科目が二重にカウントされるのを防ぎます。

### 必修要件の3つの書き方

1. 科目名一致
   - 例: 「卒業研究A」
   - 科目名が完全一致する科目で充足とみなします。

2. 代替科目記法
   - 例: 「微積分A//['微積分1', '微積分2']」
   - メインの科目名が見つからない場合、代替科目群の全てが存在してかつ合格評価であることを条件に判定します。

3. タグ記法
   - 例: 「情報::4」
   - 科目番号のタグに該当する科目群をまとめて見て、指定単位以上であれば充足とみなします。

### 特別な扱い

- 「認」評価の英語科目については、科目番号プレフィックスに読み替える処理を行います。
- すでに必修判定で使った科目は、選択判定では使われません。

## 6. 選択判定のルール

必修判定の残りの科目を対象に、選択要件を順に処理します。

### 選択要件の要素

各選択要件には、次の情報を持たせています。

- 科目番号プレフィックス群
- 最低単位数
- 最高単位数
- 除外要件かどうか
- 表示名
- 属するグループ番号

### 判定の考え方

- 科目番号のプレフィックスが一致する科目を候補として拾います。
- 例えば `*タグ` がある場合は、事前定義された科目番号タグに対応する科目群を自動展開します。
- 除外要件の場合は、「対象プレフィックスに該当しない科目」をマッチ対象とします。
- 要件の定義順に評価し、その場で消し込みを行います。

### 重要なポイント

- 選択要件間でも同じ科目を二重計上しないようにしています。
- そのため、重複する科目番号の要件があっても、先に使った科目は後続要件では扱われません。

## 7. グループ集計と 5 区分へのマッピング

選択要件ごとに取得した科目を、要件データにあるグループ単位でまとめます。

### グループ単位の集計

各グループについて、次の 2 系統を数えます。

- 確定単位: 履修中を除いた単位数
- 見込み単位: 履修中を含めた単位数

さらに、各グループには最大単位数が設定されているため、超過分は上限でキャップされます。

### 5 区分への変換

要件データのグループ表示名は、TsukuHub の 5 区分にマッピングされます。

- 必修科目
- 選択科目（専門）
- 選択科目（専門基礎）
- 選択科目（共通）
- 選択科目（関連）

対応が取れないグループは、5 区分集計には含めず、別の欄に記録されます。

## 8. 全体サマリーの計算

全体の要件充足状況は、必修単位数と選択単位数を合わせて算出します。

- 必要単位数 = 必修合計 + 選択最低単位数
- 確定取得単位 = 必修確定単位 + 選択確定単位
- 見込み単位 = 必修見込み単位 + 選択見込み単位
- 不足単位数 = 必要単位数 - 取得済み単位数

選択単位についても、選択グループの合計が最低単位数を超える場合には、最低単位数でキャップされます。

## 9. GPA と A 率の計算

### GPA

GPA は、次の評価を対象に計算します。

- A+
- A
- B
- C
- D

以下は GPA の対象外です。

- P
- F
- 認
- 履修中

計算式は、対象評価の単位数に点数を掛けて平均した値です。

### A 率

A 率は、A+ と A の単位数を、A+/A/B/C の合格評価の総単位数で割って求めます。

- 分母・分子は、D / F / P / 認 / 履修中を除外した評価のみで計算します。
- 対象がない場合は null として扱います。

## 10. 結果オブジェクトの内容

最終的な結果は、次の情報を持つオブジェクトとして返されます。

- 要件情報（学類・専攻・入学年度）
- 全体サマリー
- 不足単位数
- GPA と A 率
- 5 区分ごとの進捗
- 必修・選択ごとの詳細結果
- 対象外として見送られた科目

## 11. 現状の特徴と注意点

- 同じ科目を重複してカウントしないように設計されています。
- 5 区分に対応しないグループは、集計対象外になります。
- すべてがクライアント側で完結するため、オフラインでも動作します。
- 対応対象は要件データが存在する学類・専攻・年度に限定されます。
- 「履修中」は確定単位ではなく見込み単位として扱われます。
