残件の原因別整理・全25対象の索引・学校への未送信確認文案は [REMAINING_WORK.md](./REMAINING_WORK.md) を参照する。

## 1. 目的と判定基準

`GradRequirement` が公式の学群等履修細則をどこまで表現できているかを、次の4点で監査する。

1. 必修・選択・合計単位
2. 専門、専門基礎、共通、関連の区分下限・上限
3. 区分内の科目群別最低単位、科目数、授業形態などの個別条件
4. 補集合規則が卒業要件外科目を誤って計上しないこと

監査状態は次のとおり。

- **確認済み**: 公式PDFの合計・区分・主要な個別条件を回帰テストで固定した。
- **一部確認**: 合計・区分は照合したが、個別条件または年度間共用の根拠が残る。
- **重大リスク**: 現行ルールが公式表の条件を失っており、誤判定につながる具体例がある。

「確認済み」は要件IDが対応する全年度を意味しない。年度を明記していない要件は、現在確認した
公式PDF年度だけを指す。

## 3. 横断的に確認した問題

### 3.1. 合計値テストだけでは個別条件の欠落を検出できない

`remainingCollegeRequirements.test.ts` は公式表の必修・選択合計と5区分の下限を固定しているが、
区分内の複数列を単一matcherへまとめてもテストが成功する。社会工学類と地球学類で追加したように、
`requirementItems` の最低単位配列と、片側だけ取得した場合に未充足になることを検証する必要がある。

### 3.2. 共通ビルダーの補集合規則が教職・博物館科目を除外する（部分修正済み）

`humanitiesSocial.ts` と `humanHealthArts.ts` の関連科目規則は `isExcludeRequirement: true` であり、
その除外コード側に教職・博物館タグを入れている。この形式では教職・博物館科目は関連へ入らない。
公式表で関連科目として明記されている学類について、明示規則を補集合より先に置く必要がある。
人文学類、日本語・日本文化学類、社会学類は2024年度表に基づく明示規則へ変更した。
その他の学類は個別表の確認後に修正する。

### 3.3. 学士基盤科目の個別最低単位が共通科目合計へ平坦化される（修正済み）

両共通ビルダーは、学士基盤、体育、外国語、情報、国語、芸術を一つの規則にまとめ、その規則へ
最低1単位を設定している。このため、学士基盤科目を0単位しか履修していなくても、選択の体育等が
1単位あれば個別条件を満たした扱いになる。公式表で学士基盤1単位を要求する全要件について、
学士基盤規則とその他共通科目規則を分離する必要がある。
2026-10-23に両共通ビルダーを分離し、代表7要件の回帰テストを追加した。

### 3.4. 複数タグ間でexceptが誤って波及する（修正済み）

従来のmatcherは、複数タグを一つのincluded/excepted集合へ展開していた。このため、教職タグが
除外する99系が、同じ規則に明示した博物館タグでも除外されていた。タグごとに包含・除外を評価して
から和集合を取るよう修正し、教職9系と博物館99系が同じ規則でともに計上されるテストを追加した。

### 3.5. ルール版の年度間共用

人文・社会・人間・医学・体育・芸術系の多くは、単一要件IDを2022〜2026年度へ割り当てている。
この形式自体は維持する。要件IDの末尾はルール版の識別子であり、適用入学年度は `supportedDepartments.ts` を正とする。
新年度PDFを前年度と比較し、判定内容が同じなら既存要件IDへ年度を追加し、意味上の変更がある場合だけ
新しい要件IDを作る。今回の具体的照合は主に2024年度PDFであり、同一性を確認していない年度まで
「確認済み」とは扱わないが、年度ごとの不要な定義複製は行わない。

年度更新時は、合計、区分、個別最低単位、必修科目、注記を比較する。科目名変更が読み替えで安全に
吸収できる場合は同じルール版を維持する。卒業要件ルールが同じ場合でも、授業形態等を持つ科目カタログは
年度ごとの固定スナップショットを生成する。

### 3.6. 必修合計と必修科目配列は別々に監査する必要がある

`compulsorySumUnit` が公式表と一致していても、`compulsory` に科目名が不足していると、履修済み科目を
必修へ割り当てられない。医学、看護、医療科学では、公式表の必修科目一覧と配列を一科目ずつ照合する。

## 4. 生物学類の授業形態判定

年度別科目JSONには `course_number`、`course_name`、`method` が保存されているため、科目番号から
授業形態を補完する案は実現可能である。ただし、現在の卒業判定用軽量スナップショットは同一授業番号だけを
保持していたが、2023〜2026のEB15〜EB99に限り授業形態の導出値と方針IDを追加した。

以下の手順で実装した。残る制約と分類表の承認事項は `audits/biology.md` を参照する。

1. KdB CSVの「授業方法」コードと、講義・演習・実験・実習の対応を年度ごとに検証する。
2. 卒業判定用軽量スナップショットへ、必要な科目だけの授業形態を追加する。
3. `Course` にカタログ由来の授業形態を追加し、成績CSVの値と混同しない型にする。
4. `SelectRequirementTuple` の単位下限とは別に、科目数下限と授業形態別科目数下限を表す制約型を追加する。
5. 同一授業・読み替え科目を重複して科目数へ数えない。
6. カタログ未収録年度や授業形態不明時は、条件を充足扱いにせず「確認不能」として表示する。

外部DBを実行時に直接問い合わせる方式は、DB障害やデータ更新によって同じ成績CSVの判定結果が変わるため
採用しない。固定した年度別静的成果物を使う。

5. 社会工学・物理・化学（HR-024〜026）の年度監査を実施。応用理工学類（HR-027）の4主専攻・2023〜2026も監査済みで、全25対象に証拠表が揃った。横断整理と確認文案は `REMAINING_WORK.md` に保存済み。次は同書の手元項目と回答取得後の反映。HR-021の卒業論文正式番号、HR-022の指定一覧、HR-023の認定・番号対応等は学校への確認事項。情報科学類SSの追加比較（HR-019）は利用者方針で保留。既監査学類の未解決条件・独立承認も残る。

各修正では、公式表の個別列を先に失敗テストとして追加し、その後に要件データを変更する。
