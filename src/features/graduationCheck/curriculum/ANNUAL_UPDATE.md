# 次年度開始前の卒業要件・科目カタログ更新手順

最終更新: 2026-10-28

## 1. この手順の目的

新年度の入学者を卒業要件判定の対象へ追加する前に、公式の学群等履修細則と科目カタログを
固定し、前年度との差が判定結果へ影響するかを確認する。

卒業要件と科目カタログは別々に管理する。

運用対象は4年制2023年度以降、医学類は既存の2022年度以降。未整備年度は追加せず、
看護・医療科学を6年制の医学類と混同しない。対象範囲を縮小するときは、以前の索引に掲載された対象外の
生成物を内容・ハッシュを保って `curriculum/archive/` へ移してから再生成する。`compiled/` に
索引外の古いJSONを残さない。旧レビュー記録もアーカイブし、現行年度の確認事項から範囲外年度だけの項目を外す。

- **卒業要件ID**は年度そのものではなく、判定内容が変わった時に作る「ルール版」である。
- **科目カタログ**は授業形態、同一授業、科目番号変更が年度ごとに変わり得るため、毎年度の
  静的スナップショットを作る。
- 入学年度の要件を、履修した授業の開講年度カタログを使って判定する。両者を混同しない。

## 2. 実施時期

日付は大学の公表時期に合わせて動かしてよいが、公開直前にまとめて行わない。

| 目安 | 完了させる作業 |
| --- | --- |
| 新年度開始の3か月前まで | 公式PDFの公開状況確認、担当範囲と未解決ルールの洗い出し |
| 2か月前まで | 前年度PDFとの意味差比較、要件IDを継続するか分岐するか決定 |
| 1か月前まで | 新年度科目データの固定、スナップショット生成、代表科目テスト |
| 2週間前まで | 全テスト・Lint・ビルド、画面での受入確認、未対応学類の公開停止確認 |
| 新年度開始時 | 公開版PDF・最終科目データの再確認、出典日・ハッシュ・監査結果を記録 |

公式資料または必要な科目属性が揃わない場合、推測で新年度を対応対象に加えない。

## 3. 必要な入力

- 新年度版の公式「学群等履修細則」PDF
- 比較元となる前年度版PDF
- 新年度の固定KdB CSVまたは、それから生成した年度別授業JSON
- 現行の `RequirementId`、`supportedDepartments.ts`、要件データ
- `RULE_AUDIT.md` に残る未対応条件
- `HUMAN_REVIEW.md` に残る人手レビュー項目

PDFはURLだけでなく、取得日、対象年度、印刷ページ番号とPDFページ番号、ファイルハッシュを残す。
科目データも取得元、スナップショット日、上流コミット、SHA-256を固定する。

## 4. 公式PDFの意味差を判定する

各学類・主専攻について、少なくとも次を一項目ずつ比較する。

1. 卒業必要総単位、必修合計、選択合計
2. 専門、専門基礎、共通、関連の最低・最高単位
3. 必修科目名、選択必修、代替関係
4. 区分内の科目番号群ごとの最低・最高単位
5. 科目数、授業形態、学年、履修順序など単位数以外の条件
6. 除外科目、教職・博物館科目、自由科目の扱い
7. 表の脚注、米印、欄外注記

差分は次の3種類に分類する。

- **表記差のみ**: 誤字修正、レイアウト変更、安全な科目名読み替え。既存ルール版を継続する。
- **カタログ差のみ**: 科目番号、同一授業、授業形態だけが変化し、卒業要件の意味は同じ。
  要件IDは継続し、年度別カタログを更新する。
- **意味差あり**: 単位数、必修、科目群、除外、注記の条件が変わる。新しい要件IDを作る。

「差が見つからなかった」だけでは不十分で、上の7項目を確認した記録がある場合だけ既存IDを
新年度へ適用する。

## 5. 要件データを更新する

### 意味差がない場合

1. `supportedDepartments.ts` で新年度を既存の要件IDへ対応付ける。
2. 要件データの `header.enrollYear` 表示範囲を更新する。
3. 新年度が既存IDへ解決されるテストを追加する。
4. `RULE_AUDIT.md` に比較したPDF年度と結論を記録する。

年度名だけを変えた要件定義の複製は作らない。

### 意味差がある場合

1. `RequirementId` に新しいルール版IDを追加する。
2. 変更部分だけを暗黙に継承せず、実行時に必要な完全な要件を生成する。
3. `supportedDepartments.ts` で新年度だけを新IDへ割り当てる。
4. 旧年度が旧IDのままであること、新年度が新IDになることを両方テストする。
5. 合計値だけでなく、小区分の最低単位配列と片側不足の失敗例をテストする。

現行の型で表せない科目数、授業形態、主専攻分野などの条件は、単位数へ近似しない。制約型を
追加してから対応するか、その学類・年度を未対応として表示する。

## 6. 年度別科目カタログを固定する

1. 新年度のKdB CSVを固定し、元URL、取得日、ファイル名、SHA-256を記録する。
2. CSV列、文字コード、授業方法コードの意味が前年と同じか確認する。
3. 年度別授業JSONと卒業判定用軽量データを生成する。
4. 同一授業リンク、科目番号読み替え、必要な授業形態を代表科目で照合する。
5. `catalog/README.md` の年度、件数、リンク数、ハッシュを更新する。

```sh
npm run sync:catalog-assets
```

既存の固定成果物だけからカリキュラム用スナップショットを再生成する場合は次を使う。

```sh
npm run sync:curriculum-catalog
npm run sync:graduation-catalog
```

生成後は必ず差分を確認する。外部DBへの実行時問い合わせや、同じ年度ファイルの無告知上書きは
行わない。

卒業要件も、差分ではなく年度別の完全スナップショットを生成する。

```sh
npm run sync:requirement-snapshots
```

出力先は `curriculum/compiled/<入学年度>/<学類キー>/<主専攻キー>.json` である。各主専攻について完全な
`GradRequirement`、意味的SHA-256、監査状態を保持する。年度別 `index.json` とルートの
`manifest.json` も同時に生成される。年度差分はレビュー資料に限定し、
判定処理の入力にはしない。`rule-reviews.json` が `approved` でないスナップショットは
`publishable: false` となり、本番切替対象にしてはならない。

## 7. 公開前の検証

最低限、次をすべて成功させる。

```sh
npm test
npm run lint
npm run build
git diff --check
```

さらに、各変更学類で次を画面またはテストから確認する。

- 未履修、最低単位ちょうど、1単位不足、上限超過
- 一方の小区分だけを十分に履修した場合が未充足になること
- 必修科目が選択・関連へ流れないこと
- 教職、博物館、自由科目、認定単位の扱い
- 同一授業を重複計上しないこと
- 入学年度と授業開講年度を変えた組合せ
- 別学類の科目・ルールを自動入力や分類が参照しないこと

## 8. 公開可否チェックリスト

- [ ] 新年度PDFの出典、取得日、ページ、ハッシュを記録した
- [ ] 前年度との7項目比較を全学類・主専攻で完了した
- [ ] 既存ID継続または新ID作成の理由を記録した
- [ ] `supportedDepartments.ts` の新年度対応をテストした
- [ ] 新年度科目カタログと軽量成果物を固定した
- [ ] 未対応制約を近似せず、対象外表示または実装で処理した
- [ ] 全テスト、Lint、ビルド、`git diff --check` が成功した
- [ ] `CURRENT_STATUS.md`、`RULE_AUDIT.md`、`HUMAN_REVIEW.md` を更新した
- [ ] 公開後に戻せる旧成果物とコミットを特定した

一つでも未確認の必須項目があれば、その学類・年度は対応済みにしない。部分的に公開する場合は、
未対応の学類・年度を選択肢から除外し、理由を利用者へ表示する。

## 9. 更新記録のひな型

```text
対象年度:
公式PDF:
取得日 / SHA-256:
比較元ルール版:
意味差: なし / あり
判断理由:
新しい要件ID（意味差ありの場合）:
科目カタログ元データ / SHA-256:
未対応条件:
テスト結果:
確認者 / 確認日:
公開可否:
```
