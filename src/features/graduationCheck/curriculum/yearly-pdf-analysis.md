# 2023〜2026年度PDFの比較結果

## 結論

現在の正規化形式は、公式表の二軸分類、合算条件、読み替え、履修順序などの
**卒業要件そのもの**を表す土台としては継続利用できる。ただし、4年度分を比較すると、
次の情報を追加しないまま運用するのは危険である。

1. PDFの版年度と学生の入学年度を分ける
2. PDF内ページ番号と冊子上の印刷ページ表示を分ける
3. 表セル・注記を「モデル化済み／対象外／要確認」のいずれかへ対応付ける
4. 成績CSVに存在しない科目属性を、実行前に科目番号・科目名へ解決する

このため `SourceDocument`、`SourceReference`、`sourceCoverage`、
`MatcherResolution` を正規化形式へ追加した。

## 年度間で確認できた差異

- 2023年度版は縦長中心の旧様式、2024年度版以降は横長の多列表が中心である。
  同じ内容でもセル座標やページ構造を使い回せない。
- 2024年度版には学群単位のPDFしおりがある一方、2025・2026年度版には同等のしおりがない。
  しおりの有無を抽出処理の前提にできない。
- 2024年度版は121ページ、2025・2026年度版は127ページであり、末尾の規則・表にも増減がある。
  学類表だけを抽出して終了すると、全学的な規則や経過措置を落とす可能性がある。
- 2025年度版と2026年度版は多くのページで外形が近いが、ファイルは同一ではない。
  「前年と見た目が同じ」という理由でルールを共有してはならない。
- PDF先頭から数えたページ番号と、紙面下部に印刷されたページ番号は一致しない。
  出典参照では両者を混同しない。

## フォーマットへの影響

### 版年度と適用年度

`SourceDocument.editionYear` は資料の版、`CurriculumApplicability.admissionYearFrom / To`
は学生の入学年度を表す。両者は一致するとは限らない。経過措置は
`transitionRuleText` と該当する規則の `applicability` に保持する。

### 出典の完全性

要件に `sourceRefs` があるだけでは、「取り込んだ規則」の出典しか証明できず、
取り込まなかった注記を発見できない。そこで `sourceCoverage` に、対象学類に関係する
表セル、脚注、本文規定、経過措置を一件ずつ登録し、次のいずれかへ分類する。

- `modeled`: 正規化した規則IDへ対応付けた
- `not_applicable`: 対象外である理由を残した
- `manual_review`: 自動判定できず、人手確認が必要

これにより、未分類科目を「関連科目」へ流して辻褄を合わせるのではなく、データ作成時点の
拾い漏れと、履修データ側の未分類を別々に調査できる。

### 授業データベースがない前提

実行時の `Course` が持つのは科目番号、科目名、単位数、評価、開講年度だけである。
したがって `course_tag`、`offering_organization`、`external_designation` は公式文書を
表現するための意味的な条件ではあるが、そのままブラウザでは判定できない。

これらは正規化段階で保持し、承認前に `MatcherResolution` を使って科目番号・科目名だけの
条件へ変換する。変換できないものは警告を出し、コンパイル対象にしない。将来科目カタログを
導入する場合も、使用したスナップショットを出典文書として固定し、年度をまたいで暗黙に
最新データを参照しない。

## 推奨する処理手順

1. PDFをハッシュ・版年度・ページ数付きで登録する。
2. 対象学類の表、脚注、本文規定、経過措置をRawデータへ抽出する。
3. Rawの各断片へ安定したIDを付け、原文とPDF座標を保持する。
4. 正規化規則を作り、各断片を `sourceCoverage` で棚卸しする。
5. DBを必要とするmatcherを、成績CSVだけで実行可能なmatcherへ解決する。
6. 静的検証と人手レビューを通す。
7. 学類・入学年度ごとの完全な実行用スナップショットへコンパイルする。
8. 既存チェッカーとの回帰比較と、未分類・複数一致の監査を行う。

作成時の重複を減らすために前年版から差分入力することは構わないが、ブラウザが読む成果物は
継承関係を残さない完全なスナップショットとする。これにより、前年データの修正が別年度へ
意図せず波及することを防ぐ。

## 次の実装単位

最初から全学類を一括変換せず、表の形と注記が複雑な学類を含む小さな代表集合で
Raw→Normalized→実行形式を通す。その際、以下を合格条件とする。

- 関係する出典断片がすべて棚卸しされている
- 未解決matcherとコンパイル阻害の手動確認項目がない
- 未分類科目が「どの規則にも一致しない」と明示され、例外区分へ自動計上されない
- 複数規則に一致した科目が監査結果に残る
- 入学年度ごとの回帰テストがある

## 2023年度・情報科学類パイロットで判明したこと

`pilots/coinsSoftwareScience2023.ts` に、ソフトウェアサイエンス主専攻の2023年度入学者向け
パイロットを置いた。PDF第83・85ページ（冊子242・244ページ）を根拠とし、表と注1〜15を
`sourceCoverage` で棚卸ししている。

合計は必修54単位・選択71単位・総計125単位で2026年度と同じだが、関連科目欄は旧科目番号
体系を使う。「E、F、G、Hで始まる科目、共通科目及び教職に関する科目」以外を6〜10単位、
E・F・GC・GE・H科目を0〜4単位として年度固有のmatcherにした。注7の複数科目番号は
2023年度KDB固定スナップショットで解決し、注15の4組の旧科目読み替えも保持している。

注10の実験履修条件、学類長が判断する同内容科目、外国人留学生向け選択、単位互換は成績CSV
だけでは解決できないため、`manual_review` のままコンパイルを止める。留年・3年次編入・
早期卒業は今回の対応範囲外である。

## 2024年度・情報科学類パイロットで判明したこと

`pilots/coinsSoftwareScience2024.ts` は、PDF第84・86ページ（冊子247・249ページ）の表と
注1〜15を根拠にする。2023年度と表の内容は同じだが、PDF第83ページ（冊子246ページ）にある
令和5年4月1日施行改正の経過措置も `applicability` の根拠として棚卸しした。

関連科目は引き続きE・F・G・Hを用いる旧科目番号体系である。2024年度KDBスナップショットでは、
除外区分と同じ授業として開設される関連科目候補が42科目となり、2023年度の48科目とは一致しない。
この差分があるため、表の規則が同じ年度間でもカタログ解決結果は共有せず、年度別に固定する。

## 2025年度・情報科学類パイロットで判明したこと

`pilots/coinsSoftwareScience2025.ts` は、PDF第85・87ページ（冊子251・253ページ）の表と
注1〜15を根拠にする。PDF第84ページ（冊子250ページ）には令和7年4月1日施行改正があり、
施行日前の入学者には従前の履修方法を適用する旨を `applicability` の根拠として記録した。

関連科目は2024年度と同じ旧科目番号体系だが、2025年度KDBで二重開設として除外される候補は
40科目である。2023年度48科目、2024年度42科目、2025年度40科目と年度ごとに変化しており、
固定スナップショットを年度別に持つ必要性を確認できた。

## 2026年度・情報科学類パイロットで判明したこと

`pilots/coinsSoftwareScience2026.ts` に、ソフトウェアサイエンス主専攻の表を
正規化したパイロットを置いた。PDF第85・87ページ（冊子253・255ページ）を根拠とし、
表の合計値、注記、読み替え、卒業研究履修条件まで別々の規則として保持している。

既存の `coins-ss-26` と主要な必修・選択単位数は一致した。一方、関連科目については
既存形式が「除外条件に一致しない残りの科目」を自動計上するのに対し、公式注6は、同じ科目が
GA・GB・GC・GE・共通科目・教職科目としても開設されている場合には関連科目として扱わない。
成績CSVには二重開設情報がないため、成績CSV単独ではこの例外を正確に判定できない。

そこで2026-10-16版のKDB CSVをSHA-256と上流コミット付きで固定し、備考欄の「同一」記載を
同一授業グループへ変換した。補集合は `all_courses` で母集合を明示し、除外区分と同じ授業として
開設される14科目を科目番号で追加除外する。これにより注6の手動確認は解消したが、KDBに記載の
ない同内容科目や個別許可条件は引き続き `manual_review` とする。
