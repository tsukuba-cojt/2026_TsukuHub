# 卒業要件監査 開発引き継ぎ

最終更新: 2026-10-28

この文書は、別チャットや別担当者が卒業要件監査を中断地点から再開するための入口である。
詳細な経緯は `CURRENT_STATUS.md`、横断的な監査結果は `RULE_AUDIT.md`、人による確認事項は
`HUMAN_REVIEW.md` を参照する。

## 1. 現在の目的と作業方針

**2026-10-28 対応年度の再整理（最優先）**:
4年制課程の運用・今後の必須監査は2023年度以降に限定する。看護・医療科学も4年制。
6年制の医学類だけ既存の2022〜2026対応を維持し、未整備の2021年度は追加しない。
現行の年度・主専攻スナップショットは `compiled/` の198件（5年度索引＋manifest込み204 JSON）。
利用者の明示依頼で情報メディア創成学類の2026を追加し、2025と同じ25版を使う。4年制の2022以前は対象へ戻さない。
対象外になった2021年度4件・2022年度46件は内容を変更せず `archive/compiled/` へ移し、過去のレビュー16件も
`archive/rule-reviews-out-of-scope.json` に保存した。PDF・監査結果・比較用の旧ルール版は保持する。
対応年度の正は `supportedDepartments.ts`。共用中の `*-22` を消さず、範囲外の年度を選択肢や生成物へ戻さない。
以下の過去の調査範囲・経緯は比較記録。2022年度だけの未確認事項を今後の必須監査へ戻さない。

**2026-10-27 最新の利用者方針（以下の過去監査記録より優先）**:
利用者の最新依頼で詳細監査を再開した。人文学類（HR-013）・心理学類（HR-015）・障害科学類（HR-016）・地球学類（HR-017）の技術監査・修正を実施済み。
利用者方針でSSの追加比較（HR-019）は保留し、学類の監査を優先する。全25対象の監査記録が揃った。残件は `REMAINING_WORK.md` に横断整理済み。次は同書の手元項目と、回答取得後の条件反映を進める。詳細監査を進めても、次の5分類運用方針は維持する。
詳細データ・監査を保持したまま、当面のプロトタイプは5分類の粗い単位集計で運用する。
未分類の利用者入力は必修・専門・専門基礎・共通・関連の5種類を維持する。
詳細条件の不足・確認不能で5分類の進捗を減算しない。画面で所属コースを必須にせず、
個別条件の確認は履修細則で本人にも確認するよう促す。運用・情報収集と並行して詳細監査を進め、
監査途中の確認不能を画面の5分類集計へ混ぜない。

`checkGraduationWithCatalog` は `five-category` 方式、内部純粋関数の既定値は監査用 `detailed`。
手動分類後もレポートの `evaluationMode` を引き継ぐ。詳細の小区分上下限・科目数上限と
5分類の区分上限を分離し、必要総単位と5分類の下限・上限を使って集計する。
`unsupported`・公開不可という以下の記録は**詳細判定の承認状態**であり、5分類のプロトタイプ運用の
禁止を意味しない。未解決条件の解決や詳細ルールの承認と同一視しない。

全学類・専門学群の卒業要件を、配置済みの公式PDFと年度別の固定科目データに照合し、現行判定が
公式表の条件を失っていないか監査する。監査は全対象で `AUDIT_METHOD.md` の `audit-v1` を使う。

- 公式PDFはリポジトリ内の `curriculum/2021.pdf`〜`2026.pdf` を使う。インターネットから勝手に取得しない。
- PDFのテキスト抽出はページ発見の補助に限り、表の列、結合セル、脚注はページ画像で確認する。
- 科目DBは科目番号、科目名、授業形態、同一授業の照合に使い、卒業要件そのものの根拠にはしない。
- 年度差は差分だけを実行時入力にせず、年度・学類・主専攻ごとの完全なスナップショットとして保存する。
- 意味が同じ年度は同じ要件IDを使い、判定結果が変わる年度だけ新しい要件IDへ分ける。
- 表現できない条件を単位数へ近似しない。`unsupported` または `needs_review` として残す。
- 自動監査が完了しても、人による独立レビューが終わるまでは `approved` にしない。

2026-10-28最新修正: 利用者指定で知識情報・図書館2026を必修43・選択81・基礎30〜50として追加。
化学2026の上段80という指摘は拡大画像で82と確認して撤回。化学の実行数値42／82は変更不要。
既存画面は実行時GradRequirementを5分類で使用し、監査スナップショットのpublishableを公開判定へ流用しない。
DBスキーマ変更・正規化形式への全面切替は不要。工学システム・応用理工の残件は後続対応とする。
既存画面用API→カタログ補完→5分類→手動再計算をテスト済み。保存サービスの既存テストも成功。
実ブラウザ・本番DBの実接続は今回未検証。全体Lintは既存の別機能7エラー・2警告を再確認。
Gitに未追跡の実行時定義・番号対応・テスト・生成物がある。新規ファイルもコミット対象へ含める。
この作業ではコミット・プッシュ・デプロイは行っていない。

## 2. 現在までに完了した基盤

- 自動分類が別学類の回答を参照しないよう、表示中の卒業要件と同じ学類の回答だけへ限定した。
- 個別分類・一括分類後の再計算とDB保存、分類履歴の取得を実装した。
- 卒業判定で小区分、内数、除外、二重計上を扱う仕組みと回帰テストを拡充した。
- `NormalizedCurriculum` 1.1へ科目数、授業形態、学期、学生の分野・コース、判定不能時の
  `unknown` 方針を追加した。
- 年度別生成物を
  `curriculum/compiled/<入学年度>/<学類キー>/<主専攻キー>.json` に分割した。
- 現行対象198件の完全な主専攻スナップショットを生成している（2022年度は医学類の2件のみ）。
  年度別 `index.json` とルート `manifest.json` を含めるとJSONは204ファイル。過去50件は `archive/` に保存した。
- 次年度更新手順を `ANNUAL_UPDATE.md` に記録した。

注意: 人が編集する正規化要件の正式な配置は
`curriculum/requirements/<入学年度>/<学類キー>/<主専攻キー>.ts` と決めたが、現時点の同ディレクトリは
READMEだけである。実行時ルールは引き続き `data/requirements/*.ts` にあり、正規化形式から実行形式への
コンパイラと既存ルールの段階的移行は未完了である。
