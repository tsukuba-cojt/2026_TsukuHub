## 1. 現在地と「確定不能」の分け方

25対象すべてに監査記録がある。通常4年制は2023〜2026、医学類だけ既存の2022〜2026が運用範囲。
知識情報・図書館2026も利用者指定の43／81で運用対応済み。旧年度の記録は比較用であり、4年制2022以前の追加監査を必須作業に戻さない。

現行 `compiled/` の年度×主専攻198件を集計した結果は次のとおり。

| 状態 | 件数 | 意味 |
| --- | ---: | --- |
| unsupported | 136 | 詳細条件に未表現・情報不足等がある。136個の独立問題や136人の利用者という意味ではない |
| needs_review | 62 | 実装・検証を記録しているが独立レビュー等が残る。学校の回答だけで全件解決するとは限らない |
| approved | 0 | 人による独立承認の記録はまだない |
| publishable: true | 0 | 詳細判定の承認状態。5分類プロトタイプの利用可否とは別 |

同じ問題が複数年度・主専攻に重複するため、問い合わせは以下の原因別にまとめる。
この件数から「回答1件で何人分・何件減る」とは算定しない。回答で解決した条件と残った条件を確認して更新する。

| 原因 | 主に必要な情報・作業 | 進め方 |
| --- | --- | --- |
| 公式表の不整合 | 正しい単位数・適用年度・訂正資料 | 学校の回答が必要。数値を推測で置き換えない |
| 指定・除外・読み替え一覧がない | 科目番号付きの年度別正式一覧 | 学校に資料を確認。固定DBの同一授業情報は候補の照合に使う |
| 個人ごとの認定・属性 | 言語特例、移行前取得、所属領域、単位互換、早期卒業等 | 当面は本人確認と既存5分類。詳細入力を必須にしない |
| 実装に配分・属性判定がない | 公式条件が明確な範囲の設計・境界例・実装 | 手元で進められる。学校へアルゴリズムの承認を求める問題とは分ける |
| 履修開始時点が分からない | 主専攻選択・実験・卒研開始前の履修履歴 | 卒業時点のCSVから推測しない。粗い集計へ混ぜない |
| 独立レビューが未実施 | 別の確認者による資料・実装・検証の確認記録 | 学校回答の受領と区別し、確認者・日付を記録する |

## 4. 手元で進める順序

1. **5分類の具体的な誤分類を優先**する。利用中に番号・年度・学類・期待区分が分かったものを再現し、
   既存の成功／不足／除外テストにまとめる。成績表の収集・送信や、入力項目の追加は今回行っていない。
2. **番号対応の残件**を固定DBと正式資料で照合する。開講年度と入学年度を分け、番号が見つからないことを廃止・誤記の証拠にしない。
3. **配分器の要件を切り出す**。物理・化学等では親合計と内数だけで各欄上下限を同時充足する割当を証明できない。
   科目の分割可否・余剰振替の公式ルールが明確な例から、単位ではなく科目ごとの境界例を作る。
   既存5分類の集計方式は維持し、詳細未対応を解消したことにしない。
4. **独立レビューを準備**する。62件のneeds_reviewも含め、年度別証拠と検証結果を示す。
   承認は別の確認者の確認者名・確認日・対象条件が揃ってから記録する。

## 5. 回答を受け取った際の扱い

回答ごとに、対象HR／質問番号、回答資料、適用入学年度・主専攻、確認できた条件、残った条件を記録する。
一つの回答で関連する全年度を一括承認しない。正式番号表で確定した部分だけ実行定義へ反映し、
変更に必要な境界テストを実施して年度別スナップショットを再生成する。
学生個人の認定・所属・取得時点は一般の科目対応表と分ける。本人確認が必要なままの条件は残す。
画面は引き続き必修・専門・専門基礎・共通・関連の5分類で、詳細未確定を理由に進捗を減らさない。

本書の集計は現行198スナップショットから取得し、25対象と監査記録の対応を照合した。
今回は監査索引・文案の整理であり、外部への連絡・承認状態の引き上げ・UI項目追加は行っていない。
