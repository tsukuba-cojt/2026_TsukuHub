# 卒業要件ルール共通監査方法

監査方式: `audit-v1`  
制定日: 2026-10-27

## 1. 目的

学類や表の形が異なっても、監査の証拠、判断順序、状態判定を同じにする。個別学類の事情に応じて
補足章を追加してよいが、本書の必須工程と記録項目は省略しない。

## 2. 必須工程

2026-10-28現在の運用・今後の必須監査範囲は、4年制課程は2023年度以降、医学類は既存の2022年度以降とする。
看護学類・医療科学類は4年制に含める。範囲内でも未整備の年度を自動で対応対象にしない。
対象年度の正は `data/supportedDepartments.ts`。過去のPDF・監査記録・ルール版は比較資料として保持するが、
対象外年度だけの確認不足を現行の承認条件へ加えない。IDの末尾22と対応入学年度を区別する。

すべての学類・主専攻を次の順序で監査する。

1. **対象範囲の固定**
   - 学類、主専攻、入学年度、要件ID、対応範囲外を先に記録する。
2. **公式資料の固定**
   - `officialSources.ts` の文書ID、SHA-256、PDFページ数を確認する。
   - 各主専攻についてPDFページと冊子の印刷ページを記録する。
3. **表の目視確認**
   - テキスト抽出は検索の補助に限る。ページ画像で列境界、結合セル、脚注記号を確認する。
4. **年度比較**
   - 合計、区分、科目群、内数・上限、除外、必修名、注記を前年とセル単位で比較する。
   - 判定結果が変わる差だけ新しい要件IDにする。表記差だけなら理由を記録して同じ版を使う。
5. **公式条件の転記**
   - 「合計 → 区分 → 科目群 → 内数・上限 → 除外 → 必修名 → 注記」の順に証拠表へ記録する。
   - 公式表にない条件を推測で加えない。表現不能な条件を近似して充足扱いにしない。
6. **科目DBとの照合**
   - 科目DBは科目番号、科目名、授業形態、同一授業の確認にだけ使う。
   - 卒業要件そのものの根拠にはせず、対象年度の固定スナップショットを参照する。
7. **実装との比較**
   - 各公式条件を実装箇所へ一対一で対応させ、下記の状態語彙を付ける。
8. **境界テスト**
   - 最低値で成功、1単位または1科目不足で失敗、上限、除外、内数、二重計上防止、年度ルーティングを確認する。
   - 条件が存在しない項目は「該当なし」と記録し、テストを捏造しない。
9. **人によるレビュー**
   - 自動監査者とは別の確認者が、出典ページ、列境界、年度差、実装、境界テストを確認する。
   - 人の確認が終わるまで `approved` にしない。

## 3. 状態語彙

| 状態 | 意味 |
| --- | --- |
| `modeled` | 公式条件を現行型で表現し、境界テストがある |
| `partial` | 一部を表現しているが、条件またはテストが不足している |
| `unsupported` | 現行型や入力情報では安全に表現できない |
| `needs_review` | 実装・自動検証はあるが、人による独立レビューが未完了 |
| `approved` | 証拠表、実装、境界テストを人が確認済み |

`modeled` は条件単位、`needs_review` / `unsupported` / `approved` は年度別ルール全体の状態として使う。

## 4. 監査記録の必須項目

各 `audits/*.md` は冒頭に次を記録する。

```text
監査方式: `audit-v1`
レビューID: `HR-...`
監査状態: `needs_review` / `unsupported` / `approved`
対象年度: ...
要件ID: ...
回帰テスト: `...test.ts`
```

本文には最低限、次の内容を含める。

- 対象範囲と対応範囲外
- 年度・文書ID・PDFページ・印刷ページ
- 年度差と要件IDを分けた理由
- 合計、区分、科目群、内数・上限、除外、必修名、注記の処理状態
- 科目DBを使った場合の対象年度と用途
- 修正した誤判定
- 未解決事項と人による完了条件
- 追加・更新したテストと検証結果

## 5. レビュー用チェックリスト

- [ ] 対象主専攻と年度に漏れがない
- [ ] 文書ID、PDFページ、印刷ページが記録されている
- [ ] ページ画像で表の列と注記を確認した
- [ ] 年度差を合計値だけでなく全行・全注記で比較した
- [ ] 合計と区分下限だけでなく小区分・内数・上限を記録した
- [ ] 必修科目名を科目DBまたは実CSV表記と照合した
- [ ] 除外条件と補集合の母集合が明示されている
- [ ] 同じ科目を二重計上しないことを確認した
- [ ] 成功・不足・除外・年度境界のテストがある
- [ ] 未表現条件を `partial` または `unsupported` として残した
- [ ] `HUMAN_REVIEW.md` と `rule-reviews.json` の状態が一致する

## 6. 例外の扱い

学類固有の分野選択、所属班、授業形態、履修順序などは追加章で詳述する。ただし監査工程自体は
変更しない。共通手順で表現できないことを理由に監査方法を変えず、未解決条件として明示する。
