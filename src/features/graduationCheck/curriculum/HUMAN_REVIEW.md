# 卒業要件ルール 人手レビュー台帳

最終更新: 2026-10-28

残件の原因別整理・全25対象の索引・学校への未送信確認文案は [REMAINING_WORK.md](./REMAINING_WORK.md) を参照する。

この文書は、卒業要件ルールのうち**人が公式資料を読み、判断または承認する必要がある対象**を管理する台帳である。
`RULE_AUDIT.md` は技術的な監査結果、本書は人が次に行う作業を示す。未完了項目に対応する年度別スナップショットは、
`rule-reviews.json` で `approved` にしてはならない。


2026-10-28の範囲整理後、本台帳の作業対象は4年制の2023年度以降と、医学類の既存2022年度以降とする。
以下の対象年度は運用範囲を表す。過去の2021・2022年度調査は比較資料として保存するが、
対象外年度だけの未確認事項を現行の承認条件へ含めない。原記録は `audits/` と `archive/` に保持する。
ルール版IDの22を理由に、現行年度で共用しているルールを削除・改名しない。

## 1. 読み方

優先度は次の意味で用いる。

| 優先度 | 意味 |
| --- | --- |
| P0 | 現行ルールが誤判定する具体的な可能性が高い。公開判断の前に専門知識を持つ人の確認が必須 |
| P1 | 一部は実装済みだが、公式表の注記・科目群・年度差の照合が未完了 |
| P2 | 主な条件は監査済み。別年度にも同じルールを適用できることの証拠確認が必要 |

状態は `未着手`、`確認中`、`要修正`、`確認済み` のいずれかにする。`確認済み` にできるのは、公式資料の年度・ページ、
判断内容、確認者、確認日が記録され、対応する回帰テストが通った場合だけである。

## 5. レビュー記録の書式

監査作業は [`AUDIT_METHOD.md`](./AUDIT_METHOD.md) の `audit-v1` を全学類で使用する。
学類固有の補足章は追加できるが、出典固定、年度比較、処理状態、境界テスト、人によるレビューの
工程を置き換えたり省略したりしない。

各IDの確認時は、次を本書の末尾または対応する `audits/*.md` に残す。卒業要件そのものは、表の行と注記の対応が追えるよう、
「合計」「区分」「科目群」「内数・上限」「除外」「必修名」の順で表にする。長い文章だけで要件をまとめない。

```text
レビューID:
対象学類・主専攻・入学年度:
公式資料ID / PDFページ / 印刷ページ:
確認した表の行・注記:
実装上の判断:
未解決事項:
追加・更新したテスト:
確認者:
確認日:
状態: 確認済み / 要修正
```

## 6. 台帳の更新規則

1. 独立して判断できる問題は別IDにし、複数学類を曖昧に一行へまとめない。
2. 公式PDFの年度とページを確認する前に `確認済み` にしない。
3. 実装できない条件は近似せず、利用者に未対応と示したうえで `rule-reviews.json` を `unsupported` にする。
4. 実装後も、人の確認記録と境界テストがそろうまでは `approved` にしない。
5. 新年度の作業では本書を複製せず、既存IDの対象年度を広げるか、意味差があれば新しいIDを追加する。
6. 比較文化学類2022年度は合意済みの対応範囲外であり、本台帳の対象に戻さない。
